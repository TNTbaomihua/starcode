# 追星消费记账本

面向追星人群的消费记账 PWA：**本地优先 + 账号云同步**。
账本默认存在设备浏览器（IndexedDB）里，断网也能记；注册账号后自动同步到云端，**换新手机登录同一账号即可恢复全部数据**。

## 功能

- **明星档案**：自定义昵称 + 上传头像，卡片式列表，可编辑 / 删除（删除时可选择「连账单一起删」或「账单保留为无归属」）
- **记账**：所属明星 → 消费分类 → 名称 / 价格 / 日期 / 备注，支持**相册上传**与**拍照上传**图片凭证（最多 9 张，超 5MB 自动压缩，可预览 / 删除）
- **分类**：全局共用，内置 8 类（演唱会、交通费、酒店费、代言周边、潮牌、文化周边、助农产品、其他），支持任意自定义新增 / 改名 / 删除；跨设备重复的分类会自动归并
- **统计（双模式）**：
  - 单个明星统计：该明星总额、分类柱状图 / 占比饼图 + 分项列表、趋势图、流水
  - 全部总统计：总支出、各消费大类占比、各明星开销对比、Top 5、全部流水汇总
  - 年份可切换（本年 / **Σ 总统计**（全部年份累计）/ 自定义）
- **账号与云同步**：
  - 注册 / 登录（用户名 + 密码，密码 scrypt 加盐哈希存储）、密保问题自助找回密码、登录后修改密码
  - 登录后**自动双向同步**：本机账本上传云端，云端账本拉回本机，多设备之间增量合并
  - 记账 / 删除 / 改分类后 2.5 秒自动推送；回到前台、网络恢复时自动拉取
  - 删除采用「墓碑标记」同步，不会出现「这台删了、那台又冒出来」
  - 未登录也能正常使用，注册时本机已有数据会自动上传
- **数据安全**：JSON 一键导出 / 导入备份、存储配额超限提醒、金额两位小数无浮点误差

## 技术栈

原生 HTML + CSS + JavaScript，前端零依赖、零构建。服务端为零依赖的 Node HTTP 服务。

- 数据存储：IndexedDB（`idols` / `records` / `categories` 三张表，每条数据带全局唯一 id、`updatedAt`、`deletedAt`）
- 用户资料：localStorage
- 图表：原生 Canvas 手绘（柱状图 / 折线图 / 饼图 / 环形图），适配深色主题
- 离线：Service Worker（页面网络优先 + 静态资源缓存优先 + 版本化更新；`/api/*` 不缓存）
- 图片处理：`createImageBitmap` 读取 EXIF 方向自动纠正、HEIC 检测提示、大图压缩
- 云端：`server.js`（Node 内置模块，无 npm 依赖）+ JSON 文件落盘，scrypt 密码哈希 + Bearer Token 会话

## 目录结构

```
.
├── index.html               # 页面结构（3 个 Tab + 各类弹层 + 登录注册）
├── style.css                # 深黑 + 冷紫渐变主题样式
├── app.js                   # 业务逻辑（存储、渲染、图表、账号界面）
├── sync.js                  # 云同步模块（合并算法、拉取 / 推送、换机恢复）
├── server.js                # 云端服务（账号 API + 静态资源托管）
├── package.json             # 启动脚本（npm start）
├── manifest.json            # PWA 清单（可安装到主屏幕）
├── sw.js                    # Service Worker 离线缓存
├── icons/                   # PWA 图标（192 / 512 / maskable）
├── make_icons.py            # 图标生成脚本（Python + Pillow，可选）
├── data/                    # 运行时生成：账号与云端数据（勿提交到 git）
└── .nojekyll                # GitHub Pages 必需（阻止 Jekyll 处理）
```

## 本地运行

```bash
node server.js          # 默认 3000 端口
PORT=8080 node server.js   # 指定端口
```

浏览器打开 `http://localhost:3000`。账号数据落在同目录的 `data/` 中（`users.json`、`u_<id>.json`）。

## 部署

### 方式一：带云同步（推荐）

部署为 **Node 服务**（平台需支持单端口 HTTP 服务），保持 `index.html` 与 `server.js` 同级即可，启动命令 `npm start` 或 `node server.js`。

> 服务只监听 `PORT` 环境变量指定的单一端口，数据以 JSON 文件形式保存在应用目录内，无需外部数据库。

### 方式二：GitHub Pages（仅离线版）

GitHub Pages 只能托管静态文件，**账号与云同步功能会自动隐藏**，App 以纯本地模式运行（数据仍可正常记账、导出 / 导入备份）。

1. 新建 GitHub 仓库（Public），把本目录文件上传到仓库根目录
2. **Settings → Pages** → Source 选 **Deploy from a branch** → Branch `main` + `/(root)` → Save
3. 等 1~2 分钟，访问 `https://<用户名>.github.io/<仓库名>/`

## 安装到手机 / 桌面

- **iPhone**：用 **Safari** 打开链接 → 底部「分享」→「添加到主屏幕」
- **Android**：用 **Chrome** 打开 → 右上角 ⋮ →「安装应用」（或点页面底部安装横幅）
- **电脑**：Chrome / Edge 地址栏右侧的安装图标 ⊕

安装后以独立窗口全屏运行，断网也能用。

## 换手机 / 多设备使用

1. **旧设备**：设置 → 注册账号（本机已有账本会自动上传）
2. **新设备**：打开同一网址 → 底部引导里登录同一账号 → 账本自动恢复
3. 之后两台设备各自记账，都会自动合并到云端，互不覆盖

> 同一账号的云端数据上限 300MB（图片凭证占主要体积），超出会提示清理。

## 注意事项

- 数据按**网址来源**隔离：从旧网址换到新网址，浏览器里那份本地数据不会自动跟过去。请先在旧地址「设置 → 导出全部数据」，再到新地址「设置 → 导入备份」；已登录账号的则直接登录即可恢复。
- 清除浏览器数据 / 卸载浏览器会抹掉本地记录，云端账号数据不受影响（重新登录即可）。
- iOS 无痕模式下浏览器禁止写入 IndexedDB，App 会给出提示，请用普通模式打开。
- 微信内置浏览器兼容性较差，建议点右上角「⋯ → 在浏览器中打开」。
- 忘记密码：登录页「忘记密码」→ 输入用户名获取注册时设置的密保问题 → 答对即可重置。
